# 场景一：插件作者管理社区

[← 返回使用指南](/guide/) ｜ 相关文档：[团队内部协作](/guide/scenario-team) ｜ [会话分享广场](/guide/scenario-share-square)

你是 DSH 插件或技能的作者。用户在 DSH 里用你的插件，但反馈散落在 Issue、群聊、私信里 —— 报错截图没上下文，复现步骤说不清。这个场景把「发版公告 + 反馈收集 + 分流讨论」放进一个你自己的社区。

对用户的额外要求只有一条：**装 DSH**。他们已经装了。

## 一、目标与最终形态

| 频道 | 类型 | 用途 |
| --- | --- | --- |
| `公告` | 公告 | 发版说明、breaking change，全员只读 |
| `使用交流` | 文字 | 日常提问与讨论 |
| `问题反馈` | 话题 | 一个 Bug 一条话题，附复现步骤 |
| `内测` | 文字 | 提前验证版本，靠频道权限隔离 |

角色：`@everyone`（所有用户）+ `维护者`（少数协作者）。

## 二、建社区

1. 面板 **＋** → 创建社区，可见性选 **公开**。
   - 公开社区会出现在「发现」页，用户按名称 / 简介能搜到你；列表展示活跃度，对拉新有帮助。
2. 首次创建时「公告」频道已自动生成，并带一条**置顶开箱指南** —— 它本身就是一个「社区怎么用」的示例，你可以直接改写它。
3. 让用户自己来：把邀请码发到你的插件 README 里；或者用 **主动邀请**（按用户名或邮箱），对方会收到**站内信 + 邮件**。

## 三、频道怎么配

- **公告**（公告类型）：默认对 `@everyone` 只读，全员进社区即订阅。发版说明、已知问题、升级须知都发这里，并**置顶**（需要「管理消息」权限）。
- **使用交流**（文字）：默认配置即可，用户自由提问。
- **问题反馈**（话题）：这是本场景最关键的频道。用户提 Bug 前先在主面板看到所有已有话题，避免同一个问题开十遍；每条话题独立成串，回复不会互相淹没；24 小时无人回复自动归档，有人回复即恢复。
- **内测**（文字）：用频道权限把它对 `@everyone` **deny** 掉「查看频道」，再对 `维护者` 角色 allow。这样普通用户连这个频道都看不到。

频道菜单支持改名 / 改主题 / 删除，以及上移 / 下移排序 —— 把 `公告` 和 `问题反馈` 排前面。

## 四、「维护者」角色怎么勾

社区自带 `@everyone` 与一个预置「管理员」角色。**别直接用那个预置角色** —— 它按全部权限位初始化，权限过大。新建一个 `维护者`：

**勾这些：**

- `查看频道` `发送消息` `创建讨论组`
- `管理讨论组`（归档 / 删除已解决的问题话题、标记解决）
- `管理消息`（把结论置顶、删掉误发内容）
- `邀请成员`

**不要给：**

- `管理角色` —— 给了就能自建角色并给自己加权限
- `管理社区` —— 改资料这类事留在自己手里
- `封禁成员` —— 除非确实需要协助处理骚扰

关于「踢人」：如果你希望维护者能清理广告号，给 `移除成员`（踢出后可重新加入）比给 `封禁成员` 更安全。

两条硬规则会保护你：**层级防提权**（维护者动不了 owner），**不能授予自己没有的权限位**（他们勾不出你没有的权限）。

## 五、日常运营动作

- **发版**：在 `公告` 发 Markdown 说明（支持代码块），配 `@everyone` 提醒并置顶；旧版本公告取消置顶即可。
- **收反馈**：让用户在 `问题反馈` 里一条一话题。你自己在话题里回复时，结论会留在串里，后来的人能搜到。
- **让用户贴证据**：截图、日志、`cordis.yml` 片段可以直接**粘贴或拖拽**进输入框（一条消息最多 4 个附件，单文件 50 MiB）。
- **最有用的一招 —— 让用户分享会话**：报错说不清时，让用户在 DSH 里把出问题的会话**分享到社区**。你点开卡片就能**克隆到自己的 DSH**，在完全一样的上下文里复现。这比来回追问十轮有效得多。
- **沉淀 FAQ**：把高频结论整理成一条消息并置顶。
- **搜索历史**：用消息搜索按关键词找，用频道 / 作者 / 时间范围 / 仅 `@我` 收窄。

## 六、交接与治理

- **加协作者**：成员面板 → 选中对方 → 分配 `维护者` 角色。
- **换人**：移除角色即可；需要彻底阻止其回来就**封禁**，随时可在成员面板解封。
- **移交社区**：如果你不再维护这个插件，用**转让所有权**把社区交给接任者。注意转让后你自己就不再是 owner，删社区 / 转让这类操作只有新 owner 能做。
- **封禁名单**：有 `封禁成员` 权限的人可在成员面板查看和管理，解封后此人可凭邀请码重新加入。

## 七、常见坑

| 现象 | 原因 / 处理 |
| --- | --- |
| 用户说收不到邀请 | 邀请是「站内信 + 邮件」双通道；若 Server 未配置 `RESEND_API_KEY`，邮件不会发，让对方看面板里的收件箱 |
| 用户看不到 `内测` 频道 | 这就是预期行为；确认对方已有 `维护者` 角色 |
| 新人看不到某个频道 | 检查角色是否勾了 `查看频道`，以及频道权限覆盖里有没有对该角色 deny |
| 公告频道发不了言 | 公告默认对 `@everyone` 只读；给自己或 `维护者` 在频道权限里 allow `发送消息` |
| 想改预置「管理员」角色的权限 | 可以直接改，也可删掉 —— 它就是个普通角色，不会自动分配给任何人 |
| 话题串「消失」了 | 24h 无人回复自动归档，回复即恢复 |
| 自建社区报错 | 自建上限 20 个，且每 24 小时最多创建 5 个 |
